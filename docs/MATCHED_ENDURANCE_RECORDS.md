# Recorded endurance campaigns

The latest verified fortress view follows each of the six matched attempts
from its decision-64 baseline through later audited windows. It does not use
live observer files, private saves or inferred completion. A missing later
record keeps the verified baseline visible and says that no endurance result
has been published. It does not classify the live run as absent or failed.

Each publication registers the result and window file, their exact digests,
and immutable result/declaration commits. Validation reproduces the declared
window from its full own-save lineage, keeps the original model and conditions,
and checks cumulative responses, tokens and game ticks. It rejects reordered,
repeated or borrowed saves and changes to the declaration. Later multi-segment
windows and exact-cursor admission pauses retain the same save boundaries.
The final decision-1280 record is readable without implicitly extending its
budget. CLI preparation and the website reuse the same package-level pure
window constructor; the API does not depend on the uninstalled scripts package.

The table shows one latest saved result per attempt, not the sum of overlapping
window totals. Different saved response counts are visibly unequal budgets;
neither the table nor same-seed repeated attempts establish a general ranking.
Individual window details are created only when opened, so longer histories
do not immediately create thousands of hidden table rows. Exact metrics,
per-decision observations, source-load/final-reload proofs, clock outcomes,
teardown and immutable evidence links remain inspectable.
